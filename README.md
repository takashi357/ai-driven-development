# 業務判断を支援するWebアプリの試作と検証

## 概要（30秒で読めます）

- **何を作ったか**：業務上の判断を支援する2つのWebアプリです。
  1. **ローカルLLM活用診断・PC分担作業台** — 手持ちのPC（メモリ8GB／16GB）で、ローカルLLMを業務のどこにどう使えるかを判断する
  2. **補助金・助成金ガイド** — AI導入・人材育成に使える公的制度を、受給者・条件・上限を分けて整理し、条件付きで試算する
- **私の役割**：要件定義、判断ロジックの設計、検証観点の設定、出典・結果の確認です。実装とテストコードの作成にはAIコーディング支援を使い、動作・出典との照合と修正の判断は私が行っています。
- **見どころ**：動いてはいるが判断の役に立たない試作品を、どう見抜き、どう仕様と検証を変えて直したか（下記「改善の具体例」）。
- **位置づけ**：個人による試作・検証です。受託案件や導入実績ではありません。

関連リポジトリ [local-llm-record](https://github.com/takashi357/local-llm-record) では、ローカルLLMを閉域の実機で動かし、出力を原典と照合した測定記録を公開しています。

## 改善の具体例

### 条件を変えても、診断結果がほとんど変わらなかった

初期版は画面も動き、文面も変わっていました。しかし結果を集計すると、16GB環境の54条件のうち39条件で、推奨の出発点が同じ4B級モデルに偏っていました。この偏りを指摘し、用途と優先度に応じて、比較するモデルの範囲と最初に示す作業方針が変わるよう仕様を改めました。

検証方法も、「文面が変わるか」を見るものから、「期待する結果になるか」を確かめるものに変えました。例えば、16GBで用途を下書きから要約に変えると比較範囲が変わること、外部送信の可否だけを変えた場合は必要メモリが変わらないことを確認しています。108通りの画面操作は、この判断ルールを検査するものです（モデル自体の性能測定ではありません）。

### 補助上限の一覧を、条件付きで検討できる形に変えた

補助金の上限額を並べるだけでは、受給者の違う制度や対象外の費用まで合算してしまいがちです。そこで、受給者を自社・顧客・大学や自治体などに分けて表示し、研修人数を増やしたときの年度上限、制度変更時に以前の資格条件を引き継がないこと、入金年が未定の助成を収支に含めないことなどを仕様に加え、テストで確認しました。

複数制度の上限額を合計した「受給可能総額」は表示しません。資格が未確認の試算と、条件を満たすと仮定した試算も区別します。計算と候補判定は[13本の回帰テスト](funding-guide/tests/funding.test.cjs)で、画面の挙動は[23項目の操作記録](funding-guide/docs/browser-verification.json)で確認できます。

## 前提と注意点

- 「28」は収録している制度・枠の数で、受付終了・予告段階のものや融資・現物支援も含みます。個別の受給資格や採択を判定するものではありません。
- 8GB→16GBは作業の分担です。2台のメモリを合算したり、推論を分散したりするものではありません。
- 書き出すJSONと指示文には原文がそのまま含まれ、暗号化はしていません。
