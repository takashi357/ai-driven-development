# AI駆動型開発｜業務の判断を、使える試作品へ

樋口隆史が、利用者の目的・制約・改善要求を整理し、AIに実装と検証を依頼した2つのWebアプリです。**私が担ったのは、何を作るか、どこが判断に役立たないか、どう直すかを具体化することです。** AIがコード・テスト・資料整理を作成し、操作結果や出典と照合しながら修正しました。

採用・面接では、業務上の問いを仕様に変え、試作品の問題を見つけ、検証できる形へ直す過程をご覧いただけます。個人による試作・検証であり、顧客への本番導入や売上・工数削減の実績は、このリポジトリでは示していません。

## 私の判断と、AIに任せた作業

## 改善の具体例

### 条件を変えても、診断が判断に役立たなかった

初期版は画面が動き、文面も変わりましたが、開発記録では16GBの54条件中39条件が4B級を出発点としていました。私の指摘を受け、AIが用途・優先度によるモデルの比較範囲と、先に示す作業方針を修正しました。

検証も、単に文面が変わるかを見る方法から、具体的な期待値の確認へ進めました。例えば、16GBで下書きから要約へ変更すると比較範囲が変わり、外部送信の可否だけを変えた場合は必要メモリを理由なく変えないことを確かめています。108通りの画面操作は、この判断ルールを検査したものです。モデルの性能測定は含みません。

### 補助上限の一覧を、条件付きの検討へ変えた

補助金・助成金ガイドでは、自社・顧客・大学や自治体等の受給者を分けています。AIの調査・検証では、研修人数を増やしたときの年度上限、制度変更時に前の資格条件を引き継がないこと、入金年が未定の助成を収支へ算入しないことなどを確認・修正しました。

複数制度の最大額を足した「受給可能総額」は示しません。投資制度は代替候補を比較し、資格未確認の試算と、条件を満たすと仮定した試算を区別します。[13本の回帰テスト](funding-guide/tests/funding.test.cjs)で計算・候補判定等を、[23項目の開発時操作記録](funding-guide/docs/browser-verification.json)で画面の挙動を確認できます。

## 外部提示時の読み方

- **独立した試作品**です。特定企業・官公庁からの受託、推薦、導入済み案件を示しません。
- **28件は制度・枠の収録数**です。受付終了・予告・詳細未確認、委託研究・返済型資金・現物支援を含み、受給できる補助金28件という意味ではありません。資料の確認日は各出典に記載し、個別の受給資格・採択は確定しません。
- **8GB→16GBは作業の分担**です。メモリの合算や分散推論は行いません。診断のモデル適性は提案で、このアプリの開発では実機推論性能を測定していません。
- **通信の確認範囲を限定**します。単一HTMLの作業台でHTTP(S)リクエストが0件だった確認と、Web配信基盤・端末全体の通信保証は別です。書き出すJSONと指示文には原文が含まれ、暗号化しません。

面接での説明文、証拠の読み方、関連リポジトリの注意点は[提示・確認メモ](docs/PRESENTATION.md)にまとめています。
