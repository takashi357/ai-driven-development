# 検証したことと、していないこと

## 元の実装で実施したブラウザー検証

2026年9月20日、実際のChromiumで画面の選択・クリック・ファイル保存と読み込みを実行しました。画面操作の自動化にはPlaywrightを使用しました。

| 対象 | 結果 |
|---|---|
| 診断の108通り | 全条件を画面から選択。欠損表示・JavaScriptエラーなし |
| 診断結果の違い | モデル表示8種類、作業方針11種類。具体的な条件変更に対する期待値も確認 |
| 情報の扱い | 外部送信不可の条件では、クラウドへ原文を送る方針を提示しない |
| JSON受け渡し | ファイルを実際に保存し、別のクリーンなブラウザー環境で読み込み |
| 仕事の切り替え | 要約・抽出・下書き・言い換えで4種類の異なる指示文 |
| 分割処理 | 原文の保持、文字数上限、分割境界の絵文字を確認 |
| 不正な入力 | 不正JSON、未知のバージョン・用途、10万文字超、1MB超を拒否 |
| 古い出力の残留 | 準備内容を編集したら旧ファイルの保存を無効化。不正な読み込み後は旧指示文を消去 |
| 文字としての表示 | 資料名・本文に含まれるHTMLを実行しない |
| キーボード・画面幅 | タブとラジオ操作。320、390、768、1024、1440pxで横はみ出しなし |
| オフラインHTML | `file://`で開き、ネットワークを無効化したブラウザーでも受け渡しが動作。HTTP(S)リクエスト0件 |
| Webホスト後 | 実URLでファイル受け渡しと4用途・ブロック切り替えを確認。本人限定の設定と、未ログイン時の閲覧遮断を確認 |

元の記録は [verification/](verification/) にあります。掲載用に環境固有のURLを取り除いています。

### ホスト先の通信を別に扱う

ローカル配信とオフライン版では、アプリからの文書送信処理がないことを確認しました。Webホストでは配信基盤のCloudflareによるセキュリティ確認のPOST通信も観測しました。HTTPメソッドだけで文書送信の有無を判定する検査は、この通信まで失敗として扱いました。

そのため、Web版の操作確認と、オフライン版の通信ゼロの確認を分けています。配信基盤の通信内容を完全に監査したわけではありません。Web版全体を「通信ゼロ」とは記載しません。[Cloudflareの公式説明](https://developers.cloudflare.com/cloudflare-challenges/challenge-types/javascript-detections/)は、HTMLへの検出コードの挿入と`/cdn-cgi/challenge-platform/`経由の処理を説明しています。

## GitHub掲載用の検証スクリプト

`tests/`は、元の検証スクリプトから実行環境固有のパスとChromium配布パッケージへの依存を外したものです。Playwrightが取得する通常のChromiumで実行できる構成としています。

```sh
npm install
npx playwright install chromium
npm run test:diagnosis
npm run test:handoff
npm run test:offline
```

検査対象はローカルの`dist/`に限定しています。実サイト用の認証トークンは不要です。出力先は`test-results/`で、Git管理から除外しています。

掲載準備時にはソースとスクリプトの構文、およびオフラインHTMLの再生成が元の成果物と一致することを確認します。上表は元の実装での検証記録であり、移植後の検証スクリプトをあらゆる開発環境で実行したという意味ではありません。

## 未検証のこと

- 実際の8GB／16GB PCでのモデル推論、応答速度、空きRAM、消費電力
- 日本語の実務品質、6B・7Bモデルと新しい小型モデルとの比較性能
- 複数人同時利用、組織の文書管理との接続、長期運用
- 官公庁や企業の利用規程への適合、実データを用いた業務導入
- 人だけで作業した場合との費用・時間の比較

診断の適性表示は提案・推定です。ブラウザーで機能が動くことと、組織の実務で有効であることを区別して評価してください。
